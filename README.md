# 업풀업 (Up-Pullup)

풀업을 매일 몇 개 했고 오늘 몇 개 해야 하는지 한 화면에서 확인하고, 체크하면 **Google 할 일(Google Tasks)** 에 완료로 올라가는 안드로이드 앱입니다.
GitHub Actions가 APK를 만들고, 앱은 스스로 새 버전을 찾아 내려받아 설치합니다.

## 무엇이 들어 있나

| 화면 | 하는 일 |
| --- | --- |
| **오늘** | 지난 기록(어제 몇 개), 오늘 목표 세트, 세트별 개수 조절·체크, 휴식 타이머, 기록 + Google 할 일 완료 처리 |
| **플랜** | 100개까지의 전체 로드맵, 진행률, 남은 세션, 완주 예상일 |
| **기록** | 누적/연속/최고 기록, 최근 14세션 막대 차트, 기록 목록(동기화 상태·재시도·삭제) |
| **AI 코치** | Gemini로 새 종목·목표·기간에 맞는 세션 계획 생성, 자유 질문 |
| **설정** | Google 연동·할 일 목록 선택, Gemini 키/모델, 운동 요일·휴식·자동 조절, 알림, 앱 업데이트, 백업/복원·CSV 내보내기 |

## 처음부터 들어 있는 플랜

첫 실행 시 **풀업 100 프로젝트**가 자동으로 만들어집니다.

- 시작: `6 / 5 / 5 / 4 / 4` = 24개 (오늘 한 기록으로 1번 세션이 이미 완료 처리되어 들어갑니다)
- 목표: `20 / 20 / 20 / 20 / 20` = 100개
- 총 48세션. 주 5일이면 약 10주.
- 규칙: 뒤쪽 세트를 앞 세트 개수까지 채운 뒤 전체를 한 칸 올립니다. 세션당 +2개, 5번째 세션마다 증가 없이 "다지기".

```
#1  6/5/5/4/4   24     #10 8/8/8/7/7   38 (다지기)
#2  6/6/6/4/4   26     #20 11/11/11/11/10  54
#3  6/6/6/6/4   28     #30 14/14/14/14/14  70
#4  6/6/6/6/6   30     #40 18/17/17/17/17  86
#5  6/6/6/6/6   30     #48 20/20/20/20/20 100 🎉
```

초기 기록이 마음에 안 들면 **기록** 탭에서 지우면 됩니다. 목표를 못 채우면(자동 조절 ON) 같은 세션을 한 번 더, 크게 초과하면 한 세션을 건너뜁니다.

## 빌드와 배포

- `main` 또는 `claude/**` 브랜치에 push하면 GitHub Actions가 APK를 빌드합니다.
- **기본 브랜치** push와 `v*` 태그 push는 릴리스를 발행하고 APK를 첨부합니다. 버전은 `1.0.0.<run_number>` 형태입니다.
- 앱은 시작할 때(설정에서 끌 수 있음) 그리고 **설정 → 앱 업데이트**에서 GitHub 릴리스를 확인하고, 더 높은 버전이면 내려받아 설치합니다.

### 서명 키 — 넣지 않아도 됩니다

키가 없으면 CI는 debug 키로 서명합니다. 앱은 정상 동작하지만 서명이 빌드마다 달라져서 두 가지가 막힙니다.

1. **덮어쓰기 설치 불가** — 새 버전을 깔려면 기존 앱을 지워야 하고, 지우면 기록도 함께 사라집니다.
   그래서 앱에 **백업/복원**을 넣어 두었습니다. 아래 순서면 기록은 그대로 살아납니다.
   `설정 → 데이터 → 백업 파일로 저장` → 기존 앱 삭제 → 새 APK 설치 → `백업 파일에서 복원`
   (설정의 앱 업데이트 카드에도 같은 안내와 백업 버튼이 함께 뜹니다.)
2. **Google 할 일 연동 불가** — Android용 OAuth 클라이언트는 서명 인증서의 SHA-1에 묶여 있어,
   지문이 매번 바뀌면 등록해 둘 수가 없습니다.

Google 연동까지 쓰려면 키를 한 번 만들어 등록하세요.

> 이 저장소는 **공개** 상태입니다. `.jks` 파일과 base64 문자열은 커밋하지 말고,
> Actions 아티팩트로도 올리지 마세요. 공개 저장소의 아티팩트는 누구나 내려받을 수 있습니다.

```bash
keytool -genkeypair -v -keystore pullup-release.jks \
  -alias pullup -keyalg RSA -keysize 2048 -validity 10000

base64 -w0 pullup-release.jks    # 이 값을 시크릿에 넣습니다
keytool -list -v -keystore pullup-release.jks -alias pullup | grep SHA1
```

저장소 **Settings → Secrets and variables → Actions** 에 등록합니다.

| 이름 | 종류 | 값 |
| --- | --- | --- |
| `KEYSTORE_BASE64` | Secret | 위 base64 문자열 |
| `KEYSTORE_PASSWORD` | Secret | keystore 비밀번호 |
| `KEY_ALIAS` | Secret | `pullup` |
| `KEY_PASSWORD` | Secret | 키 비밀번호 |
| `GOOGLE_OAUTH_CLIENT_ID` | **Variable** | `123-xxxx.apps.googleusercontent.com` |

`pullup-release.jks` 파일은 저장소에 커밋하지 말고 따로 보관하세요.

## Google 할 일이 동작하는 방식

할 일 목록이 **앞으로 할 운동을 보여주는 곳**이고, 앱과 양방향으로 맞춰집니다.

- 앱은 **다음에 할 세션 하나**를 미완료 할 일로 올려 둡니다 (`풀업 26개 (6/6/6/4/4)`).
- **기한 규칙은 한 줄입니다 — 오늘 뭐라도 했으면 내일, 아직 안 했으면 오늘.**
  - 방금 끝낸 세션 때문에 다음 것이 다시 오늘로 잡히지 않습니다.
  - 하루에 여러 세션을 해도 모레·글피로 밀려나지 않고 내일에서 멈춥니다.
  - 며칠 건너뛰어 기한이 지났으면, 앱을 열 때 오늘로 당겨집니다.
  - 운동 요일 설정은 여기서 보지 않습니다. 쉬는 요일이어도 달력상 내일로 잡습니다.
  - **오늘** 탭의 목표 카드 제목도 이 기한을 따릅니다. 오늘 몫을 이미 끝냈으면 `다음 목표 · 내일`로 바뀝니다(미리 해도 되고, 기록하면 당겨서 한 것으로 남습니다).
  - **플랜** 탭의 세션 날짜와 완주 예상일도 같은 기준입니다. 다음 기한부터 **하루에 한 세션씩** 세고, 주말이나 쉬는 요일을 건너뛰지 않습니다. 이미 끝낸 세션은 실제로 한 날짜를 그대로 보여 줍니다.
- **앱에서 기록하면** 그 할 일이 완료로 바뀌고, 실제로 한 개수로 제목이 갱신된 뒤 다음 세션이 새로 올라갑니다.
- **Google 할 일에서 체크하면** 다음에 앱을 열 때 기록으로 들어옵니다. 이때는 실제 개수를 알 수 없어 **목표를 채운 것으로** 처리하고, 기록에 "Google 할 일에서 완료 체크"라고 남깁니다. 숫자가 다르면 그 기록을 지우고 앱에서 다시 넣으면 됩니다.
- Tasks에서 할 일을 지우면 앱이 다음 동기화 때 다시 만듭니다.

### 목표를 못 채웠을 때 (실패)

**어떻게 올리나:** 오늘 탭에서 세트별 개수를 **실제로 한 만큼 낮춰 입력**하고 기록 버튼을 누르면 됩니다. 합계가 목표보다 적으면 자동으로 실패입니다 — 따로 누를 버튼은 없습니다. 아예 못 한 날은 **`오늘 못 했음 (전부 0개로)`** 를 누르면 다섯 칸이 한 번에 0이 됩니다. 합계가 모자라면 기록 버튼이 **빨갛게 바뀌고 `실패로 기록하기`** 로 이름이 바뀌므로, 누르기 전에 실패로 남는다는 걸 알 수 있습니다.

한 세션의 **합계**가 목표에 못 미치면 실패로 봅니다. 세트별로 갈렸어도 합계만 채우면 통과입니다.

- 시도한 사실은 **완료로 닫습니다.** 제목이 `❌ 풀업 17개 (6/5/4/2/0) — 실패 (목표 26개, 9개 부족)`가 됩니다.
- 이어서 **같은 목표의 재도전 할 일**이 새로 올라갑니다: `풀업 26개 (6/6/6/4/4) (재도전 2회차)`. 메모에 지난 시도가 최근 5개까지 쌓입니다.
- **플랜은 전진하지 않습니다.** 채울 때까지 같은 세션이 계속 나오고, 목표를 낮추지도 않습니다. 이건 **`자동 조절` 설정과 무관하게 항상** 그렇습니다 (자동 조절은 크게 초과했을 때 한 세션 건너뛸지만 결정합니다).
- 오늘 탭 맨 위에 `재도전 N회차` 카드가 뜨고, 기록 탭에는 실패한 시도가 빨간 줄로 표시됩니다.

Google 할 일에서 체크한 기록은 실제 개수를 알 수 없어 목표를 채운 것으로 처리하므로 실패로 잡히지 않습니다. 개수가 달랐다면 그 기록을 지우고 앱에서 다시 넣으면 됩니다.

한 번에 하나만 올리는 이유는, 이 앱의 플랜이 날짜가 아니라 **완료 횟수**로 진행되기 때문입니다. 하루 건너뛰거나 목표를 못 채우면 다음 목표 숫자가 달라져서, 여러 개를 미리 만들어 두면 뒤쪽 숫자가 실제와 어긋납니다.

Google Tasks는 변경 알림을 보내주지 않아서, 앱을 **열 때마다** 확인합니다. 바로 맞추고 싶으면 설정 → Google 할 일 연동 → **지금 동기화**를 누르면 됩니다.

## Google 할 일 연동 설정

[docs/GOOGLE_SETUP.md](docs/GOOGLE_SETUP.md) 에 단계별로 정리해 두었습니다. 요약하면:

1. Google Cloud 프로젝트에서 **Google Tasks API** 사용 설정
2. OAuth 동의 화면 구성 후 본인 계정을 테스트 사용자로 추가
3. **Android** 유형 OAuth 클라이언트 ID 생성 (패키지명 `com.pullup.tracker`, 위에서 뽑은 SHA-1)
4. 클라이언트 ID를 저장소 변수 `GOOGLE_OAUTH_CLIENT_ID` 로 등록하고 다시 빌드
5. 앱 **설정 → Google 계정 연결** → **불러오기** → "운동" 목록 선택

클라이언트 ID가 없어도 앱은 그대로 동작합니다. Google 업로드 기능만 꺼진 상태가 됩니다.

## Gemini 연동

Google AI Studio에서 API 키를 발급받아 **설정 → Gemini AI** 에 붙여넣으면 됩니다. 키는 기기 안에만 저장됩니다.
키가 없어도 AI 코치 탭의 **"앱 규칙으로 만들기"** 로 같은 사다리 플랜을 만들 수 있습니다.

## 로컬 빌드

```bash
./gradlew assembleDebug
./gradlew testDebugUnitTest
```

Android SDK 35, JDK 17이 필요합니다.

## 기술 구성

Kotlin · Jetpack Compose (Material 3) · kotlinx.serialization(JSON 파일 저장) · OkHttp · AppAuth(OAuth 2.0 + PKCE) · AlarmManager 알림 · GitHub Releases 자체 업데이트. DB나 서버 없이 전부 기기 안에서 돌아갑니다.
